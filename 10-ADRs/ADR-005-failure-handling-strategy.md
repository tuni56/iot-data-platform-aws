# ADR-005 – Failure Handling Strategy

## Status

Accepted

---

## Context

Telemetry data is generated by remote industrial assets operating in challenging environments.

Failures may occur at multiple layers:

* Connectivity
* Message delivery
* Validation
* Processing

Operational visibility requires preserving failed events for investigation.

---

## Decision

Failed telemetry processing events will be routed to an Amazon SQS Dead Letter Queue.

CloudWatch alarms will monitor DLQ activity.

Amazon SNS will notify operators when failures exceed acceptable thresholds.

---

## Rationale

Discarding invalid or failed events would reduce trust in the platform and make troubleshooting difficult.

Dead Letter Queues provide:

* Failure isolation
* Operational visibility
* Replay capability
* Root cause analysis

AWS IoT rules also support error actions when downstream actions fail.

---

## Consequences

Benefits:

* No silent failures
* Improved observability
* Easier troubleshooting
* Better operational reliability

Trade-offs:

* Additional components
* Additional monitoring requirements

No telemetry event should be discarded without traceability.
